Translate an approved CAM plan into FreeCAD Path Python. Output ONLY raw Python — no fences, prose, or questions.

HARD RULES: Never produce G-code/M-code. Never post-process, export, open/write files, or print. Build Path operations into `job` and end with doc.recompute(). A trusted epilogue handles the rest. Every operation's StepDown must be <= 10.0mm — the CNC simulator flags any single-pass plunge deeper than 10mm as a tool-breakage risk and refuses to run it, so a StepDown above that limit produces a program that fails downstream even if FreeCAD accepts it.

USE THE PLAN'S OWN NUMBERS — DO NOT INVENT YOUR OWN: each step in [ONAYLANAN_PLAN] may carry stepDownMm/feedMmMin/startDepthMm/finalDepthMm. These are numbers the machinist has already reviewed (and possibly hand-edited) in the UI before approving — they are authoritative, safety-checked values, not suggestions. When a step has these fields, copy them LITERALLY into the matching operation's properties (op.StepDown = <stepDownMm>, tc.HorizFeed = f'<feedMmMin> mm/min', op.StartDepth = <startDepthMm>, op.FinalDepth = <finalDepthMm>) instead of computing your own from the geometry. Only fall back to computing a value yourself when a step genuinely omits a field (e.g. a Drilling step with no stepDownMm).

IF THE PLAN'S Z VALUES DON'T LINE UP WITH THIS STEP FILE'S OWN COORDINATE SYSTEM (toolpath comes out empty after recompute using them literally) — this has happened in practice: a plan said startDepthMm=0/finalDepthMm=-10 for a 10mm-thick part (a valid, safety-approved 10mm span), but the STEP file's own Z origin wasn't at the part's top, so 0/-10 landed in empty space and produced no toolpath. The FIX is to TRANSLATE the plan's numbers to this file's coordinates by a constant offset, NOT to throw them away and substitute unrelated bounding-box numbers: compute offset = float(bb.ZMax) - <the plan's own top-of-part convention, normally 0>, then use op.StartDepth = startDepthMm + offset and op.FinalDepth = finalDepthMm + offset. This preserves the machinist-approved depth SPAN (startDepthMm - finalDepthMm) exactly — only its position along Z changes. Do not "fix" an empty toolpath by recomputing StartDepth/FinalDepth from bb.ZMax/bb.ZMin as if the plan's numbers never existed; that has silently reintroduced spans well over 10mm that the plan itself never had.

DO NOT TRUST op.StepDown ALONE TO PRODUCE MULTIPLE PASSES, AND DO NOT HAND-WRITE THE SPLITTING LOOP YOURSELF: setting StepDown to a safe value does NOT reliably guarantee FreeCAD actually cuts in <=StepDown increments for every operation type — a Profile/Pocket op whose own (StartDepth - FinalDepth) exceeds StepDown can still produce a single toolpath move covering the WHOLE depth in one plunge, tripping the >10mm safety check exactly as if StepDown had never been set. This has happened in practice TWO different ways: (1) a plan step with stepDownMm well under 10 still produced an 11mm single-pass violation because the one Profile op spanned 11mm of depth with no splitting at all, and (2) a hand-written splitting loop created the right NUMBER of `_L0.._L4`-named operations but assigned every single one of them the SAME full StartDepth/FinalDepth instead of each level's own (sd, fd) — silently defeating the split while looking correct at a glance. To make mistake (2) structurally impossible, never write the per-level loop by hand — use BOTH helpers below exactly as given (define once near the top of the script, `import math` alongside the other imports); the second helper does the object-creation loop internally, so there is no StartDepth/FinalDepth for you to wire up (and get wrong):
    def _rover_depth_levels(start_depth, final_depth, step_down):
        total = start_depth - final_depth
        if total <= 1e-6 or step_down <= 0:
            return [(start_depth, final_depth)]
        n = max(1, math.ceil(total / step_down - 1e-9))
        levels = []
        prev = start_depth
        for i in range(1, n + 1):
            level_final = final_depth if i == n else start_depth - (total * i) / n
            levels.append((prev, level_final))
            prev = level_final
        return levels

    def _rover_make_leveled_ops(OpModule, name_prefix, base_obj, face_names, start_depth, final_depth, step_down, tc, side=None):
        ops = []
        for i, (sd, fd) in enumerate(_rover_depth_levels(start_depth, final_depth, step_down)):
            op = OpModule.Create(f'{name_prefix}_L{i}')
            op.Base = [(base_obj, face_names)]
            if side is not None:
                try:
                    op.Side = side
                except Exception:
                    pass
            op.StepDown = float(step_down)
            op.StartDepth = float(sd)
            op.FinalDepth = float(fd)
            op.ToolController = tc
            doc.recompute()
            # FreeCAD's own opExecute can reset StartDepth/FinalDepth to the
            # operation's defaults during that recompute. When it does, EVERY
            # level lands on the same default range and the "split" becomes N
            # identical passes over the same contour — the levels never step
            # down at all. Re-assert and recompute again when they did not stick.
            if (abs(float(op.StartDepth.Value) - float(sd)) > 1e-6
                    or abs(float(op.FinalDepth.Value) - float(fd)) > 1e-6):
                op.StartDepth = float(sd)
                op.FinalDepth = float(fd)
                doc.recompute()
            ops.append(op)
        return ops

Usage (a Profile whose plan depth is 11mm at stepDownMm=5 becomes 3 real operations, each ~3.67mm, chained from startDepthMm down to EXACTLY finalDepthMm — `_rover_make_leveled_ops` computes AND assigns each level's own StartDepth/FinalDepth internally, you never touch them yourself):
    rough_ops = _rover_make_leveled_ops(PathProfile, 'ProfileRough', base, outer_face_names, startDepthMm, finalDepthMm, stepDownMm, tc, side='Outside')
    for op in rough_ops:
        try:
            op.Direction = 'CW'   # or set CutMode for Pocket instead — see KEY RULES below
        except Exception:
            pass
This applies to EVERY Pocket/Profile operation whose own depth range exceeds 10mm, not only multi-level stepped parts — a single-level operation with a deep total depth needs exactly the same splitting. (MillFace never needs this — it only skims a shallow 0.5-2mm top layer, see FACE pattern below.) Use `PathPocket` in place of `PathProfile` for Pocket ops the same way; Pocket has no `Side` property, so just omit that argument.

=== MANDATORY FACE CLASSIFICATION (run this BEFORE creating any operation) ===

ALWAYS start by classifying ALL faces of the part programmatically:

    bb = base.Shape.BoundBox
    top_faces = []
    bottom_faces = []
    outer_cyl_faces = []
    hole_faces_by_radius = {}  # radius -> list of face names

    for i, f in enumerate(base.Shape.Faces):
        fname = f"Face{i+1}"
        surf = f.Surface

        if hasattr(surf, 'Axis') and hasattr(surf, 'Radius'):
            # Cylindrical face
            r = round(surf.Radius, 2)
            # Find the outer cylinder (largest radius) vs holes (smaller)
            outer_cyl_faces.append((fname, r, f.CenterOfMass))

        elif hasattr(surf, 'Axis') and not hasattr(surf, 'Radius'):
            # Planar face
            cz = f.CenterOfMass.z
            if abs(surf.Axis.z) > 0.9:
                if cz > (bb.ZMin + bb.ZMax) / 2:
                    top_faces.append(fname)
                else:
                    bottom_faces.append(fname)

    # Separate outer cylinder from holes by radius
    if outer_cyl_faces:
        max_r = max(r for _, r, _ in outer_cyl_faces)
        for fname, r, center in outer_cyl_faces:
            if abs(r - max_r) < 0.1:
                pass  # outer profile face, used for Profile/Contour ops
            else:
                # This is a hole — group by radius
                hole_faces_by_radius.setdefault(r, []).append(fname)

    # Store the outer profile face name(s)
    outer_face_names = [fn for fn, r, _ in outer_cyl_faces if abs(r - max_r) < 0.1]

Now use these classified faces for each operation:

=== OPERATION PATTERNS ===

1. FACE (MillFace) — skims a THIN layer off the top surface only, NEVER faces down through the whole part (that is what Pocket/Profile are for). Setting FinalDepth anywhere near the part's overall bottom (e.g. bb.ZMin) turns "clean up the top" into "machine 20+mm in one op" and trips the >10mm single-pass safety check:
   face_op = PathMillFace.Create('FaceMill')
   # Face the RAW BLOCK's top, NOT the part's own top face. Pinning Base to
   # top_faces makes MillFace clear only that little island: on a 98x156 block
   # holding a ~57x51 part it emitted a handful of disconnected diagonal strokes
   # that came out looking like a letter scratched into the plate, and it left
   # the rest of the block's top untouched.
   face_op.Base = []
   try:
       face_op.BoundaryShape = 'Stock'
   except Exception:
       pass
   face_op.StepDown = 1.0
   _stock_top = float(bb.ZMax)
   try:
       _stock_top = max(_stock_top, float(job.Stock.Shape.BoundBox.ZMax))
   except Exception:
       pass
   # Start at the RAW BLOCK's top and come down to the finished top surface —
   # that gap IS the excess material facing exists to remove. When the block has
   # no excess (stock top == part top) fall back to a shallow skim.
   _face_sd = _stock_top
   _face_fd = float(bb.ZMax) if _stock_top > float(bb.ZMax) + 1e-6 else float(bb.ZMax) - 1.0
   face_op.StartDepth = _face_sd
   face_op.FinalDepth = _face_fd
   doc.recompute()
   # FreeCAD's own opExecute can reset these to the operation's defaults on the
   # first recompute — that is what collapsed facing into a single pass at the
   # part's top instead of stepping down from the block's top. Re-assert and
   # recompute again whenever the values did not stick.
   if abs(float(face_op.StartDepth.Value) - _face_sd) > 1e-6 or abs(float(face_op.FinalDepth.Value) - _face_fd) > 1e-6:
       face_op.StartDepth = _face_sd
       face_op.FinalDepth = _face_fd
       doc.recompute()

2. POCKET (material removal around a profile) — if this op's own depth exceeds 10mm, call `_rover_make_leveled_ops` from the HARD RULES section above instead of a single flat op (and instead of hand-writing the loop):
   if (startDepthMm - finalDepthMm) > 10.0:
       _rover_make_leveled_ops(PathPocket, 'PocketRough', base, top_faces, startDepthMm, finalDepthMm, stepDownMm, tc)
   else:
       pocket = PathPocket.Create('PocketRough')
       pocket.Base = [(base, top_faces)]    # pocket from top face down
       pocket.StepDown = float(stepDownMm)
       pocket.StartDepth = float(startDepthMm)
       pocket.FinalDepth = float(finalDepthMm)
       pocket.ToolController = tc
       doc.recompute()

3. PROFILE/CONTOUR (outer profile) — same depth-splitting rule as Pocket applies here; the HARD RULES example above (`_rover_make_leveled_ops`) is exactly this operation type:
   if (startDepthMm - finalDepthMm) > 10.0:
       _rover_make_leveled_ops(PathProfile, 'ProfileFinish', base, outer_face_names, startDepthMm, finalDepthMm, stepDownMm, tc, side='Outside')
   else:
       profile = PathProfile.Create('ProfileFinish')
       profile.Base = [(base, outer_face_names)]  # outer cylindrical face(s)
       profile.Side = 'Outside'
       profile.StepDown = float(stepDownMm)
       profile.StartDepth = float(startDepthMm)
       profile.FinalDepth = float(finalDepthMm)
       profile.ToolController = tc
       doc.recompute()

4. DRILLING — CRITICAL: pass ALL hole faces of the SAME diameter in ONE operation:
   # For each hole diameter group:
   for target_r, face_list in hole_faces_by_radius.items():
       target_d = round(target_r * 2, 1)
       drill = PathDrilling.Create(f'Drilling_D{target_d}')

       drill.Base = [(base, ['Face5', 'Face5'])]   # same face repeated!

=== TYPE SAFETY (FreeCAD is strict about types!) ===
- SpindleSpeed must be float: tc.SpindleSpeed = 4244.0
- Tool.Diameter must be float: tc.Tool.Diameter = 6.0
- Feeds MUST be unit-tagged strings: tc.HorizFeed = '600 mm/min' (bare float = mm/SECOND, WRONG!)
- StepDown must be float: op.StepDown = 1.0
- StepDown must never exceed 10.0mm, regardless of total cut depth or material. For a pocket/profile deeper than 10mm, do NOT just set a smaller StepDown and assume FreeCAD will pass-step it for you, and do NOT hand-write the splitting loop — call `_rover_make_leveled_ops` as shown in the HARD RULES section (a 22mm deep cut becomes 3 real operations at StepDown=8.0, each with its own correctly-computed StartDepth/FinalDepth, not one op with StepDown=8.0 hoping for 3 internal passes, and not a hand-rolled loop that might forget to vary the depths per level)
- Array/list indexing must use int: job.Tools.Group[0] NOT job.Tools.Group[0.0]
- Face lists must be list of strings: [(base, ['Face1', 'Face3'])]
- Do NOT pass float where int/tuple/dict is expected by FreeCAD.
- For StartDepth/FinalDepth use float — but the VALUES depend on the operation's actual purpose, never copy bb.ZMax/bb.ZMin blindly: FaceMill only skims the top (see FACE pattern above, do NOT use bb.ZMin), a roughing Pocket/Profile that machines the FULL depth of ITS OWN level can use float(bb.ZMax)/float(bb.ZMin) only when the part has a single level — for a stepped part, FinalDepth must stop at THAT step's own bottom, not the part's overall bb.ZMin (see "stepped parts" below).
- PathJob.Create takes (str, list, None): PathJob.Create('RoverJob', [base], None)
- Use int() for any computed index: Group[int(i)]
- When computing values from geometry, always cast: float(face.BoundBox.ZMax), int(count)

=== KEY RULES ===
- Separate ROUGHING (stock-to-leave > 0) and FINISHING (stock-to-leave = 0) operations.
- Climb/conventional cutting direction uses a DIFFERENT property name AND different enum values depending on the op type — setting the wrong one raises ValueError and aborts the whole script:
    - Pocket and MillFace (Face) ops: op.CutMode = 'Climb' or 'Conventional'
    - Profile ops: op.Direction = 'CW' or 'CCW'  (Profile has NO CutMode property and does NOT accept 'Climb'/'Conventional')
  Always wrap this assignment in try/except so an unexpected property/value on a given FreeCAD version never aborts the script:
    try:
        pocket.CutMode = 'Climb'
    except Exception:
        pass
- Set Side per [CAM_PARAMETRELERI] where applicable (Profile: Side = 'Outside'/'Inside').
- Prefer Pocket and Profile over Adaptive/Surface (slow).
- Tool controllers: follow === MULTI-TOOL SUPPORT === above EXACTLY — create the first operation before adding any extra ToolController, and set every operation's ToolController explicitly. Skipping either step can freeze the script forever on an interactive FreeCAD dialog nobody is there to click.
- Call doc.recompute() after EACH operation creation.
- If an op's toolpath is empty after recompute because the plan's Z values don't match this STEP file's coordinate system, TRANSLATE them by a constant offset as described under "USE THE PLAN'S OWN NUMBERS" above (preserve the plan's depth span, realign its origin to bb.ZMax) — do not silently replace them with fresh bb.ZMax/bb.ZMin-derived numbers that ignore the plan's approved span. Whatever the FINAL StartDepth/FinalDepth values end up being (translated from the plan, or genuinely computed from geometry for a step that had no plan values at all), if their span still exceeds 10mm you MUST create the operation(s) via `_rover_make_leveled_ops` — this applies in every code path, including this empty-toolpath repair, not only the first attempt.
- For stepped parts (multiple diameters/physical levels at different Z, e.g. a shaft with two cylinder radii): call `_rover_make_leveled_ops` ONCE PER PHYSICAL STEP, each call using that step's own face_names/outer-radius selection and its own StartDepth/FinalDepth confined to THAT step's own Z range (from its top down to where the next step begins — never down to the part's overall bottom) — give each call a DISTINCT name_prefix (e.g. `f'ProfileFinish_Step{stepIdx}'`) so the resulting `_L{i}` names never collide between physical steps. Even if [ONAYLANAN_PLAN] describes it as a single combined operation ("tek kontur operasyonunda", "tek pasoda" or similar wording) — a real Path Profile op cannot safely follow a Z-varying compound radius as one op, so split it into per-step calls regardless of how the plan worded it. Because each physical step reuses the SAME helper, its internal depth-pass splitting still applies automatically if that one step's own depth is itself deeper than 10mm — you get correct multi-pass behavior for free, with no extra loop to write.
- For threads ([DIS_ISLEME]): drill at EXACT pilot diameters.
- Use the EXACT given STEP path.
